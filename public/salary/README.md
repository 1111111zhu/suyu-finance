# 薪资测算系统（已整合改版）

正式本地入口：http://localhost:3090/salary/index.html

原研发工作台与政策页中的「工资表」均进入此页面。旧 `/salary-preview/` 自动跳转到同一入口，同源浏览器中已经保存的批次继续使用。

## 核算流程

1. 新建批次，选择月份与计薪天数；通过原有 Excel 批量识别或逐项上传导入资料。
2. 计算应发，按姓名、工号、公司、部门或员工状态查找员工，进入明细修改工资项目或最终应发。
3. 进入实发阶段，使用生成的应发结果，或上传已有应发表；补充社保、公积金、个税、税后代扣。
4. 逐项修改扣款或最终实发，保存后同步结果、部门汇总与新导出的 Excel。
5. 原有工资说明从本批次最新结果生成；工资发生变化时提醒重新生成正文、重新导出附件。

顶部「核算设置」保留资料与参数、实习生日薪与字段映射、异常、核算规则和原有模板页入口。实习生日薪的单人设置、批量设置和明细编辑使用同一套调整记录。输出格式页展示实际导出字段并调用真实导出；已移除原先只显示提示、没有实际功能的模板新建/编辑/复制占位按钮。

## 实现边界

- 直接修改 `public/salary/index.html`，保留其原有上传解析、计算、批次、企业邮箱编辑桥接和输出逻辑。
- `payroll-engine.js`、`payroll-email-engine.js` 沿用原系统文件。
- `workbench-core.js` 为原函数增加批次内调整、撤销、保存与导出同步；`workbench-ui.js` 和 `workbench.css` 负责主界面；`workbench-pages.js` / `workbench-pages.css` 统一资料、日薪、异常、工资说明、输出格式和规则页。
- 应发调整、生成应发对应的实发调整、上传应发对应的实发调整分别存放，避免来源切换时混用。重复姓名需先区分；不能关联的原调整会明确提示。
- 原始输入文件只读。已经下载的 Excel 不会被回写，修改后重新导出。
- 数据保存在本浏览器、本站点的 IndexedDB；不同浏览器、端口或电脑之间不自动共享。旧预览与新入口位于同一站点时直接复用已有批次。
- 应发变化不会擅自重算个税；仍使用上传个税并提示复核。

## 本地运行与验证

双击项目根目录「启动薪资测算系统.command」，或运行 `npm run dev -- --host 127.0.0.1 --port 3090`。启动的是原完整工作台。

`node --test tests/salary.test.mjs tests/payroll-email.test.mjs tests/payroll-workbench.test.mjs`

76 项核算、导出、邮件和联动测试通过。浏览器已验证：原首页入口、新建批次、真实 XLSX 批量导入、日薪单人及批量设置、工号搜索、应发/实发明细编辑、最终金额调整、导出公式、邮件汇总、异常页、批次刷新恢复、旧地址跳转及 760px 布局。

设计参考保存在 `../salary-preview/design-reference/`。


## 全系统交互统一

- 两阶段内统一使用「准备资料 / 核对工资」路径；历史批次、工资说明和输出格式不混放阶段操作条。
- 上传页左侧资料列表，右侧固定核算面板；明细右侧集中修改或核对动作。
- 员工表支持整行进入明细；更多筛选收起，核对队列保持筛选顺序，最后一位完成后返回总表。
- 工资说明明确读取实发结果；事项编辑同步自动正文，手动正文优先保留；更新工资提取时保留邮件收件人、称呼、主题。
- 新建批次自动带入天数，月份变更同步默认名称，支持焦点循环和关闭后回到触发按钮。
- 1440px、760px、390px 页面矩阵已检查；同时验证实际文件导入、扣款编辑、导出公式与刷新恢复。

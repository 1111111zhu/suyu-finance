# 工资两阶段核算

第一阶段上传花名册、员工基本工资表、绩效考核表、考勤统计表、其他表、社保表、公积金表。个人社保、公积金在应发结果和导出中列示，仅供个税测算，不从应发扣除。在职员工的应发薪天数与实发薪天数相等时不触发假勤扣款；不等时假勤天数取病假、事假、旷工之和。入职、离职、实习生的原有专项规则继续适用。

第二阶段可上传应发工资表，并上传本阶段个税、社保、公积金、税后代扣表。上传的应发表优先，未上传则使用本批次第一阶段生成结果。移除上传表恢复生成结果。两次社保、公积金文件分别保存，不自动复用。税后代扣表表头为：姓名、水电代扣、餐费代扣、其它代扣、备注；第一阶段其他表的旧代扣字段不再叠加。

普通员工实发 = 应发 − 个人社保 − 个人公积金 − 个税 − 水电代扣 − 餐费代扣 − 其它代扣。实习生实发等于选定来源中的应发。公司总成本 = 应发 + 本阶段公司社保 + 本阶段公司公积金。

上传应发表与本批次生成应发表按姓名比对全部业务列。忽略行列顺序、受支持的表头别名和显示格式，金额按两位小数比较；空白和明确的 0 有区别。人员、字段及数值差异仅提示，不影响使用上传表计算和导出。重复姓名沿用首条计算并标记无法唯一比对。没有生成结果时显示“未校验”，仍可独立计算上传应发表。

解析失败的文件不会覆盖可用数据；缺失或无效扣款金额提示并按 0 计算。未提供任何可用应发人员数据时无法生成工资结果。

导出金额使用数值单元格和两位小数格式；实发、代扣合计和公司总成本包含 Excel 公式及缓存金额。异常记在姓名单元格批注，上传表缺失的人员记在姓名表头批注，不新增异常工作表。输入只读，生成表可直接重新导入，合计行不作为员工。

验证：`node --test 自动化测试/salary.test.mjs`；项目验证使用 `node --test 自动化测试/*.test.mjs`、`npm run lint` 和 `npm run build`。当前页面入口是 `/salary/index.html`。

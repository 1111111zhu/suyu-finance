# 工资服务器计算与发布

工资批量计算由 `/api/payroll/calculations` 创建任务，网页每 500 毫秒查询进度。任务在 Node.js 独立线程中按现有工资规则计算，以姓名索引查表。前端仅做录入、显示和单人编辑预览；源表上传后的批量重算也提交服务器。更改输入后，在服务器返回新结果前禁止导出旧结果。

计算权限复用现有登录与工资权限，任务结果与取消操作按用户隔离，写操作沿用同源检查。每个用户至多一个排队或运行任务，服务器同时执行一个任务、最多保留六个待处理任务；单请求最多 12 MiB，每个线程内存上限 256 MiB，两分钟超时。运行失败、取消或网络失败保留网页源表与上次结果。任务与临时结果放在进程内存，五分钟清理，最多保留六份结果、每份最多 16 MiB；服务重启或结果过期后需要重新计算。现有工资批次确认和入库流程保留，本次没有数据库迁移。

`calculation-model.js` 在构建前从工资页生成，避免前后端业务规则分叉。服务器必须保留 `server/payroll/calculation-thread.mjs`、工资模型与规则源文件，且以工作区根目录启动。

## 验证

- 新增计算及接口测试 10 项全部通过，覆盖姓名匹配、源表乱序、人工调整、重传后的新值、扣款、用户隔离、限流、取消、超时和真实服务器线程。
- 后台 Chrome 使用 1200 名模拟员工，约 2.3 秒完成应发计算；计算期间 10 毫秒页面计时器运行 215 次，验证实发、取消、重试和源表修改后的自动服务器重算。本机模拟结果，不代表生产服务器耗时。
- 对主分支原代码与修复后的完整工资测试作对照：均为 340 项，273 通过、62 失败、5 跳过，没有新增失败名称。旧失败须另行修复，不能宣称完整回归通过。
- 全仓库 lint 仍有既有 12 个错误，历史 GitHub CI 也因这些错误失败。新增接口、任务队列及控制器的定向 lint 通过，生产构建通过。

## 发布

`Payroll server compute release` 工作流验证后尝试发布本次用户授权的修复分支。只允许生产 secret 的服务器地址为当前财务服务器 `101.35.98.180`；配置仍指向其他服务器时立即停止，不上传资料或修改其他站点。

发布脚本 `运维脚本/deploy-payroll-compute.sh` 仅更新工资相关文件。先验证生产原文件与清单的 SHA256 匹配，再备份源码和 dist。首页只更新四个工资 URL 的版本号，保留已有登录与导航锚点；不覆盖登录文件、数据库或 systemd 配置。构建或健康检查失败会恢复文件和构建产物。原文件不同、新文件已有或已有 prebuild 时停止，以免覆盖其他修复。

本机直连、HTTP 代理和 SOCKS 代理的 SSH 尝试均在认证前断开；GitHub 发布通道的实际状态以 Actions 结果为准。代码上传或创建 PR 不等于服务器已经部署。

# 人员归集与正式工资确认

## 当前数据边界

- 当前人员与部门来自企业微信只读通讯录。首次成功同步只建立基线；其后以两次成功快照差异和系统发现时间记录新出现、不可见、部门、岗位、姓名变化。不可见不自动等同离职。
- 花名册只作辅助核对，绝不覆盖企微当前状态。冲突列出花名册原值、企微当前值、来源文件/工作表/行号、同步时间和判断原因。花名册转正日期是来源证据，不冒充企微事件。
- 管理员逐人选择企微 UserID ↔ 工资员工 UUID；姓名、工号只作候选检索，不自动作为身份键。工资数据库首次为空时，管理员可明确新建员工并关联。
- 正式跨月统计只读取当前已确认的实发工资 run。服务器草稿、演示数据、未确认版本均不进入统计；缺失月份以“无数据”展示而非零。每名员工同月若有多个已确认批次，仅取最近确认版本并返回警告；同一草稿的同月修订会更新当前版本且保留旧 run。

## 花名册表头规则

花名册导入、人员页和工资计算调用 `PayrollEngine.rosterFieldMap` / `normalizeRosterRow`。匹配不看列位置；删除空格并统一中英文括号后，标准表头优先，随后只认明确列出的同义词。重复列、同一字段命中多列或值无法判断时给出来源列与原因，需人工核对，不做模糊包含匹配。

| 工资条字段 | 标准表头 | 明确同义词示例 |
| --- | --- | --- |
| 姓名、工号 | 姓名、工号 | 员工姓名；员工编号、员工工号 |
| 签约公司、部门、职位 | 公司、一级部门、二级部门、三级部门、职位 | 签约公司；部门；三级部门名称；岗位、职务 |
| 计薪月状态、员工类型 | 是否入离职、员工类型、是否实习生 | 员工状态、入离职状态；人员类型；是否实习、实习标识 |
| 日期 | 入职日期、转正日期、离职日期 | 入职时间；转正日、转正时间；离职时间 |
| 银行资料 | 银行卡号、开户行 | 银行卡；开户银行、银行 |

完整别名由代码中的字段词典定义。银行卡及开户行只进入有权限的工资资料，工资条页面脱敏；不会发送到人员归集花名册接口或异动日志。

转正日期优先取计薪月花名册，基本工资表仅作补充。两者不一致时显示双方原值并阻止正式确认。转正落在计薪月时，转正前后应出勤天数之和必须等于本月应出勤天数，且两段工资可计算。入职 15 日绩效、实习工资及入离职假勤沿用原工资引擎。

## 本机接入

3220 本地预览在同一进程内提供 `/api/payroll`，使用私有 `PAYROLL_DATABASE_URL` 连接 PostgreSQL 17，不需要另起 3002 服务。企业微信当前通讯录与异动可通过同端口的只读人员接口查看；本机人员页的手动同步要求同源请求，但不需要管理员登录。3220 的管理员登录入口已停用，工资草稿、关联和正式入库等写入接口仍保持原有会话权限，不因人员页免登录而开放。未配置数据库时接口返回 JSON 503。正式入库仍需具备授权的独立流程，不能以本地花名册或未核实企微身份代替。

企业微信需要管理员在服务端私密环境设置 `WECOM_CORP_ID` 与指向权限 `0600` 文件的 `WECOM_SECRET_FILE`。该应用须有通讯录只读权限和正确可见范围。Secret 不放在网站代码、浏览器存储或仓库配置中。未配置时人员页明确显示待接入，不展示模拟人员，也不能正式确认身份。成功快照在后续同步失败时保留，并显示失败提示。

主要接口均沿用工资管理员 session 与写入 CSRF：`/personnel/directory`、`/directory/sync`、`/events`、`/rosters`、`/conflicts`、`/links`、`/payroll-summary`、`/workspaces/:id/confirm`。花名册仅表头、没有人员行时可预览字段规则，但不会生成当前人员或工资统计。

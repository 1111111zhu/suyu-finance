# 工资数据库字段映射

## 范围与稳定性

实现文件：`database/payroll/fields.mjs`。字段契约共 **71 项**：53 个 `PayrollEngine.fields/netFields` 导出字段、12 个工作台独有调整输入字段，以及工号、实习工资和 4 个调整计算字段。来源仅为 `public/salary/payroll-engine.js` 与 `public/salary/workbench-core.js`，均只读。

`payrollFields` 是显式声明、冻结的数组，元素也是冻结的 `{ key, label, column, type }`。`key` 沿用现有 JS 字段，`column` 是唯一、长度不超过 63 字符的安全 snake_case SQL 标识符。SQL 002 已按此契约生成，因此现有 key/column 不得随意改名；增列需通知 SQL 维护方重新生成，后续变更应走明确迁移。

本模块无第三方依赖，不连接数据库，不生成 SQL，不做人员匹配，不执行工资计算。人员主键、批次、历史记录及其约束由 SQL/DAL 管理。`name` 仅是姓名文本；即使同名也不会合并人员，不会从姓名或 `id` 补造工号。

## 类型与数据库精度

| type | 字段数 | 数据库列类型 | 规范化后的 JS 值 |
| --- | ---: | --- | --- |
| money | 44 | `numeric(18,2)` | 固定 2 位小数字符串或 `null` |
| decimal | 14 | `numeric(10,4)` | 固定 4 位小数字符串或 `null` |
| text | 9 | `text` | 原字符串或 `null` |
| date | 3 | `date` | 严格 `YYYY-MM-DD` 字符串或 `null` |
| boolean | 1 | `boolean` | `true`、`false` 或 `null` |

这里的 `money` 是应用类型标签，数据库必须使用 **`numeric(18,2)`，不能使用 PostgreSQL `money` 或浮点类型**。金额绝对值最大为 `9999999999999999.99`；decimal 绝对值最大为 `999999.9999`。SQL 生成器应通过固定类型白名单转换 `type`，列名只取契约中的 `column`；具体值使用参数绑定。

## 接口一：normalizePayrollValues(values)

输入为部分 `{ JS字段key: 原值 }` 普通对象，返回新的 `{ SQL列column: 规范值 }` 对象。只输出显式传入的字段；不补缺失字段，不修改输入。

```js
import { payrollFields, normalizePayrollValues, fromLegacyPayrollRow }
  from './database/payroll/fields.mjs';

// 仅为虚构的格式校验数据，没有真实人员资料。
normalizePayrollValues({
  employeeNumber: '00000042', bankCard: '0000000000000000',
  gross: '12.30', net: 0, grossAdjustment: '-0.01',
  payableDays: '0.125', leave: null, isIntern: false,
});
// {
//   employee_number: '00000042', bank_card: '0000000000000000',
//   gross: '12.30', net: '0.00', gross_adjustment: '-0.01',
//   payable_days: '0.1250', leave_date: null, is_intern: false
// }
```

### 校验规则

- **缺省与清空不同**：未传字段不输出；显式 `null` 原样保留；数字零和 `false` 有效；显式 `undefined` 报错。调用方不得用 `value || null` 清洗输入。
- **不静默丢失精度**：money 超过 2 位、decimal 超过 4 位小数直接抛 `RangeError`，包括 `1.230`、`1.00000` 这类尾零超位输入；不调用 `toFixed`、`parseFloat` 或四舍五入。
- **精确数值字符串优先**：通过十进制文本分解、位数检查和 `BigInt` 检查范围；输出补足固定位数。支持正负号、前导零、`.5` 和字符串首尾空白；负零统一为正零字符串。
- **有限 number 有条件接受**：普通小额数值可使用 number，但其十进制表示也必须通过上述小数位限制。大额 number 达到不能可靠区分最小单位的范围时拒绝，要求原始字符串；金额绝对值达到 `2 ** 46` 即拒绝 number。上游 number 已经丢失的精度无法恢复，精确金额、尤其大额必须从原始来源全程保持字符串。`0.1 + 0.2` 的浮点尾差会报错。
- **不宽松解析**：拒绝 `NaN`、`Infinity`、空白数值、科学计数法字符串、百分号、货币符号、千分位、内部空格、对象、布尔数值和 BigInt 输入。`1e2` 若先作为 JS number 求值，已经是 `100`；需要保留原始写法才能校验源字符串。
- **文本原样保留**：所有 text 字段必须是字符串或 `null`；不 trim，不转数值，也不把数字强制转成文本。工号、银行卡号若源头已经作为数字读取，无法恢复前导零，应在来源读取阶段保留文本。
- **严格日期**：仅接受四位年、两位月、两位日的 `YYYY-MM-DD`，验证实际公历日期与闰年，年份限定 `0001`–`9999`。拒绝 `0000` 年、无效日期、首尾空白、时间戳、斜杠日期、Excel 序列号和 Date 对象。无离职日期应显式用 `null`，不能直接用空字符串。
- **实习标识**：接受 boolean、数字 `1/0`，以及大小写不敏感、允许首尾空白的 `是/实习生/1/TRUE/Y` 和 `否/非实习生/0/FALSE/N`。不认识的标识报错，不能将任意非空字符串当 true 或未知值当 false。
- **未知 key 报错**：只接受契约的 JS key，SQL 列名和中文表头不是此接口的 key，例如 `bank_card` 需要改用 `bankCard`。错误中给出字段和原因，不回显人员字段值。
- 两个转换接口都只接受自有、可枚举的数据属性；不接受数组、类实例、Symbol、getter 或不可枚举属性，以免静默漏字段或执行额外逻辑。支持无原型的普通字典。

这些是存储格式规则，不替代业务规则：负值在数据库精度范围内可保留；天数是否应为 0–31、实习生扣款是否为零、各项合计是否勾稽，应由业务计算或 DAL 明确验证。

## 接口二：fromLegacyPayrollRow(row)

**固定返回 `{ values, unmapped }`，两个属性都是普通对象。** 此接口仅映射表头，`values` 使用 JS key 并保留源值的原类型；`unmapped` 保存原表头和原值，包括未知字段以及因优先级而未采用的重复/别名列。这样可复核所有未采用数据，不静默丢列。

```js
const mapped = fromLegacyPayrollRow({
  员工编号: '00000042', 应发工资: '12.30', 个人所得税: 0,
  个税: null, 额外来源字段: '保留待核对',
});
// {
//   values: { employeeNumber: '00000042', gross: '12.30', tax: null },
//   unmapped: { 个人所得税: 0, 额外来源字段: '保留待核对' }
// }
const columns = normalizePayrollValues(mapped.values);
// { employee_number: '00000042', gross: '12.30', tax: null }
```

调用方应先检查 `unmapped` 再决定是否导入，并显式调用 `normalizePayrollValues(values)`；仅完成表头映射不代表日期/金额有效。映射接口保留空字符串、超位小数和 `undefined`，由后续规范化步骤明确报错。

### 表头优先级与别名

优先级固定为：**精确标准中文表头 > 忽略空白及全/半角括号后的标准表头 > 精确 JS key > 已声明别名**。标准列即使为 `null`、零或空字符串也优先，不能由非空别名覆盖。多个别名并存时按下表声明顺序优先；同级等价表头保留源对象中先出现的列。所有未采用列进入 `unmapped`。

| --- | --- |

| workdays | 应发薪天数 |
| base | 工资基数 |
| effectiveScore | 绩效系数 |
| meal | 餐补合计 |
| transit | 交通补贴 |
| otherAdd | 其他加项 |
| annual / flexible / compensatory | 年假(天) / 弹性假(天) / 调休假(天) |
| sick / personal / absent | 病假(天) / 事假(天) / 旷工(天) |
| otherReduction | 其他减项 |
| social | 个人总计 |
| fund | 个人缴纳 |
| isIntern | 是否实习、实习标识 |
| dailyRate | 实习生日薪 |

## 容易混淆的字段及接入注意

1. `workdays` 是“应发薪”天数，属于 decimal，不是金额。`payableDays` 是导出结果；`actualPaidDays` 是工作台调整输入。标准“实发薪天数”映射到 `payableDays`，不会同时填两列。
2. `effectiveScore` 是导出的“绩效分数”，已有别名“绩效系数”仍映射到该字段；`score` 是工作台输入，须使用 JS key 或新增的无歧义标准表头“绩效系数（调整输入）”。
3. `probationTotal/regularTotal` 是转正前后月薪输入，与 `probationSalary/regularSalary`、`probationSubtotal/regularSubtotal` 分列保留。不会通过字段名称猜测等值、复制或计算金额。
4. `computedGross` 是**项目级调整后、应发总额目标调整前**的应发金额；`grossAdjustment` 是目标差额；最终值在 `gross`。对应关系为 `gross = computedGross + grossAdjustment`。`computedNet/netAdjustment/net` 同理。它们不是最初导入工资的历史快照，原工作台的 `_grossOriginal/_netOriginal` 等内部状态不在本契约内。
5. `grossTarget/netTarget` 是独立的人工目标输入，标准“应发工资/实发工资”仍映射最终结果 `gross/net`。目标可能只存在工作台的覆盖记录中，DAL 应明确从对应来源取值，不能默认员工计算对象一定包含目标，也不能将缺失目标补成最终金额或零。
6. `otherDeduct/utility/mealDeduct/afterTaxTotal` 是税后代扣及合计；`tax` 单列保存。实习状态、日薪和 `internPay` 同样分列。映射不会重算代扣合计，也不会因实习标识强制清零某个传入金额。
7. 工号是字符串属性，并不自动等同于数据库人员主键。当前工作台可能使用 `profile.id` 作为工号的回退值；本转换模块不会沿用该回退。调用方应明确人员主键和真实工号来源，不能按姓名自动识别人员。
8. `normalizePayrollValues` 接受部分字段，不验证应发/实发各项算式。调用方应先选取允许持久化的契约字段，不要把含 `id`、`_input`、异常数组等内部信息的整个人员对象直接传入。

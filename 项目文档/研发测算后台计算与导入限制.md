# 研发测算后台计算与导入限制

验收入口：http://127.0.0.1:3220/。本次调整仅在本地实现，未部署远程服务。

## 行为

上传区支持每批 100 份 Excel 或图片，每份 50 MiB（界面简称 MB）。图片可批量选择、拖入或粘贴，依次识别和复核，生成的 Excel 是派生文件，不占原始资料额度。图片 OCR 的字符复核保留；独立的金额复核面板删除。点击开始测算即授权服务器计算、归档及入账。同一主体同一月份使用既有的完整替换规则，所有月份在一个数据库事务中写入；归属不唯一、期间冲突或金额勾稽失败则整批回滚。

核算主体沿用现有的苏州默认值；核算年度优先读取原始资料，无明确年度时使用服务器当前年度。混合年度拒绝。本地入口的数据来源、模板和规则均保持原有版本。

## 分工

页面只保留文件选择、OCR 复核、进度和下载链接。`/api/rd/compute` 创建归属当前用户的任务；`/api/rd/compute/{id}` PUT 原始二进制文件，POST 入队，GET 进度或 `?download=0` 流式下载。资料逐份落盘，不将整批转成 Base64 JSON。每批原始资料最大 5000 MiB，另可有最多 100 份对应图片转换文件。

Excel 读取、计算和固定模板导出复用 `public/py` Python 规则，在异步启动的独立 Python 进程内执行。最多一个计算任务运行，队列最多八个，同一用户最多三个活动任务；单次计算超时十分钟，拒绝单 Excel 解压超过 512 MiB。图片转换也在独立进程执行，原有 OCR 进程限流保留。

原始资料和输出使用 SHA-256 归档；上传和归档文件限制、数据库 artifact/result 约束均为 50 MiB；图片识别的实际请求体也有流读取上限。输入、固定模板哈希只读校验，输出沿用模板结构与公式错误校验。固定模板缺失或不完整即拒绝计算。

## 运行条件与边界

服务器需 Node 22、Python 3，可通过 `RD_COMPUTE_PYTHON` 指定解释器。规则依赖使用项目已有 `public/py/vendor.zip`；OCR 环境仍使用 `RD_OCR_PYTHON`。需执行数据库迁移 015/016，归档目录需可写且非符号链接。反向代理须允许单请求至少 50 MiB；未修改任何远程 Nginx 配置。

任务队列和进度状态保留在当前 Node 进程内，最多 24 小时。关闭页面不会取消已入队任务，但浏览器尚未实现刷新后自动找回任务；进程重启不能恢复尚未结束的计算。完成的结果、原始证据及费用记录已持久归档到数据库/文件存储，可通过已有结果导出功能获取。该限制不等于文件或已入账记录丢失。

50 MiB 是压缩文件体积限制，不代表计算内存只用 50 MiB；极大的表格仍可能触发解压上限或计算超时。真实 100 × 50 MiB 的最坏负载未做完整压力测试。

## 验证

类型检查、图片识别回归、逐项目/平台事务回归；新增独立数据库端到端测试覆盖计算、固定模板导出、入账、50 MiB 原始证据归档与下载。上传测试验证第 100/101 份及 50 MiB/50 MiB+1 边界；本地 HTTP 入口实际验证 50 MiB 返回 200，超限返回 413。

## 公式导出（2026-10-13）

计算页导出现在包含源工时到最终工时、显示分配率、直接及公摊材料、工资分配、其他费用、运费分摊和项目成本汇总公式。原始金额仍为输入数值；工资公式内的 salary 数组保存原始工资金额。工资分配使用 LET 压缩重复计算，需支持 LET 的 Excel/WPS 版本；保存初始计算缓存及自动重算标记。规则尾差保持不变：运费按显示百分比分配并补至最后有效项目，其他分摊按精确权重并补至最大权重项目。以实际 22 份来源核验，2026 年 1 月总额 1,109,838.04 元。独立公式核验脚本为自动化测试/verify-export-formulas.py（需 formulas 解释器），不作为生产依赖。

## Windows Excel/WPS 兼容修正（2026-10-13）

移除 LET 和动态数组函数。工资原始数值及人员分配尾差放入模板人员工时统计合计现有 AG:AH 辅助列；工资分配通过 SUMPRODUCT、ROUND、IFERROR、IF 和跨表引用完成，保留工时、工资、材料与各项费用至主表的跨页公式。1,611 个有缓存值的公式已用独立解释器核对，差异为零；原始输入只读。页面费用名称使用 NFKC 归一化，修复直接人工显示为零的问题；结果区改为金额摘要、分类卡片和下载入口。本机无法直接运行 Windows Excel，尚未在真实 Windows Excel/WPS 中打开验证。

## 直接人工分配口径修正（2026-10-13）

本节替代上述逐人工资分配规则。后台以全部工资金额为直接人工总额，按人员工时统计合计页显示的项目工时分配率统一分配。显示分配率保留 0.01%，最后一个有工时项目补至 100%；项目直接人工为总额乘显示分配率、四舍五入至分，合计直接汇总各项目金额，不调整项目金额补差。人员薪酬差异不再改变项目分配比例。

Excel 直接人工页的 G5 为工资源金额合计；项目金额引用 G5 和对应 J43:J60 分配率，通过 ROUND 和 SUM 计算。主表继续引用直接人工页，网页摘要与入账项目金额使用同一后台分配结果。取消逐人工资 SUMPRODUCT 及 AG:AH 尾差辅助计算，不改变工时分配率算法。修改已在本地源代码实现；远程服务需部署该版本后生效。

## 组合表原表完整复制例外（2026-10-13）

用户明确授权项目分类明细汇总表这一张子表不套固定模板，完整复制核算维度与科目组合原工作表；保留原始行列、分类、小计、总计、所有借贷金额列、合并、字体和尺寸。其余模板规则保持既有约束。公式生成按原表表头自动定位费用、项目和首个借方金额列，重复金额表头取第一列；分类小计不重复进入分摊。复制逻辑不再依据模板容量筛掉非测算类别或小计。实际来源 54 行 9 列逐值核验无删减，总测算金额保持 1,109,838.04 元。

# 财务系统读取企业微信通讯录

本接入沿用任务引擎的服务端通讯录快照思路：财务工资 API 用企业微信自建应用凭据读取可见范围内的部门、在职成员，并把最近一次完整结果保存在独立表中。首次启动和之后每隔一段时间同步；工资管理员也可在“花名册”旁的“查看企微通讯录”中手动同步、搜索和核对。

同步数据只供查看。它不会建立工资员工、覆盖花名册或按姓名关联工资。工资员工继续使用原有 UUID 和花名册/任职数据；将来若需要联动，先由人工确认 `CorpID + userid` 与工资员工的绑定。

## 企业微信管理员需要准备

1. 复用现有自建应用，确认其可见范围包含财务系统需要核对的部门和成员，并具备读取通讯录基本信息的权限。无需通讯录编辑权限。
2. 将运行工资 API 的服务器出口 IP 配入该应用的企业可信 IP（若现有配置已覆盖，无需重复）。
3. 提供 CorpID；应用 Secret 由服务器管理员放入仅服务账号可读的文件，不写入代码、网页、日志或 Git。

服务端需要从环境变量读取：

```text
WECOM_DIRECTORY_SYNC_ENABLED=1
WECOM_CORP_ID=ww...
WECOM_APP_SECRET_FILE=/受控路径/wecom_app_secret
WECOM_DIRECTORY_SYNC_INTERVAL_SECONDS=21600
WECOM_DIRECTORY_MAX_MEMBERS=10000
```

完整模板见 `server/payroll/config.env.example`。未启用时现有工资 API 继续运行，通讯录入口会明确提示尚未配置。Secret 文件应使用现有生产凭据注入机制，不要把内容放进环境文件或发到聊天中。

若工资 API 按现有部署文档由 Docker Compose 运行，启用时，在原有 `compose.payroll-db.yaml`、`compose.payroll-api.yaml` 后附加 `compose.payroll-wecom.yaml`，并在 Compose 环境提供 `WECOM_APP_SECRET_HOST_FILE`（宿主机上私有 Secret 文件的绝对路径）。容器内固定从 `/run/secrets/wecom_app_secret` 读取；宿主机文件须允许容器内 `node` 用户读取。未启用通讯录的部署不需要加载该 override。

## 发布顺序

1. 用迁移账号执行 `npm run db:migrate`，应用 `006_wecom_directory.sql`。
2. 对现有受限工资 API 数据库角色执行 `npm run db:api-grants`（需设置 `PAYROLL_RUNTIME_ROLE` 和迁移账号连接串）。新授权仅覆盖通讯录快照表所需的 SELECT、INSERT 和指定列 UPDATE。
3. 在工资 API 的私有环境配置中启用上述参数，重启该服务。它会在启动后尝试同步，后续按间隔重试；同步失败时保留上一次完整快照。
4. 工资管理员登录网站，在花名册行点击“查看企微通讯录”，核对部门、人数、最近同步时间；可点“立即同步”。不要用通讯录人数代替花名册的计薪人数。

读接口为 `GET /api/payroll/wecom-directory`，手动同步接口为 `POST /api/payroll/wecom-directory/sync`。两者沿用工资管理员会话；POST 还要求同源和 CSRF token。手动同步会立即启动后台任务并返回 202，页面随后轮询状态。返回内容仅含 userid、姓名、部门、职务、直属上级和部门负责人等业务所需基本字段。

# 研发费用数据库接入

研发项目和费用台账使用独立的 PostgreSQL `rd` schema；不复用或写入工资模块的 `payroll` schema。浏览器继续在本地解析 Excel，服务器仅接收项目资料、三类费用汇总和台账摘要。

## 数据边界

- `rd.projects`：项目编号、名称、状态、预算和审计时间。
- `rd.ledger_entries`：项目费用台账。删除项目时由外键级联删除。
- `rd.import_requests`：旧浏览器数据迁移的幂等记录，防止重复导入。
- `actual` 始终由台账汇总计算，不在项目表重复存储。
- 浏览器不能直连 PostgreSQL；页面通过同源 `/api/rd/*` 路由访问服务器。

## 本机验证

```sh
npm run test:rd-db
npm run build
```

测试会自行创建并清理临时 PostgreSQL 17 实例，不会使用生产库。

## 生产部署约束

`compose.rd-db.yaml` 仅将 PostgreSQL 映射到 `127.0.0.1:5433`，应用的 `RD_DATABASE_URL` 也应使用该回环地址。实际密码只保存在服务器私有环境文件（权限 0600），不得提交到 GitHub、写入 systemd 单元或出现在终端历史中。

私有文件必须分开：Docker 使用 `rd-compose.env`；首次初始化临时使用管理员/role 密码；迁移临时使用 `rd-migrate.env`；`/etc/suyu-finance/rd-runtime.env` 只能有一项 `RD_DATABASE_URL`，并由部署脚本用 `EnvironmentFile` 注入网站服务。管理员和迁移文件在初始化成功后应移除。

首次部署需要独立的迁移 owner 和只具 `rd` schema 必需权限的 runtime role。按顺序运行：

```sh
npm run db:rd:provision
npm run db:rd:migrate
npm run db:rd:grant-runtime
```

`db:rd:provision` 用临时 `RD_DATABASE_ADMIN_URL` 创建 owner/runtime；`db:rd:migrate` 只用 `RD_DATABASE_MIGRATION_URL`；`db:rd:grant-runtime` 只授予网站需要的读、新增、删除及项目审计时间更新权限。应用进程只获得 `RD_DATABASE_URL`。已有浏览器 localStorage 不会被服务器自动读取；用户可在数据管理页选择一次性导入，导入完成后本机原始 JSON 会保留。

写入 API 还校验同源 `Origin`；公司出口 IP 白名单仍是访问边界。如需按员工区分读取、导出或删除权限，应在此基础上另行接入用户登录与角色权限。

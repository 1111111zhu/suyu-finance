# 内置 Excel 与服务器后台任务

花名册与基本工资可直接在网页工作簿中修改，支持多工作表、公式、常用格式、排序筛选和 Excel 导出。编辑器采用 Univer；复杂图表、图片、透视表、宏及外部链接不能保证原样编辑，导入时提示，原始文件另存服务器供下载。

保存后的工作簿、员工数据、原始文件和不可变历史版本存入 PostgreSQL，按登录账号隔离。同账号更换设备可复用；新月份空批次自动引用已保存的资料，历史批次引用当时版本。版本冲突返回提示，不覆盖别的设备修改。保存请求幂等，网络失败可重试。

浏览器负责显示与交互；网络与 JSON 编码在专用浏览器 Worker。文件识别、Excel 生成、保存时的公式重算、校验和数据库读写运行于服务器 Node Worker。月度源表导入和工资表导出也走服务器任务，读取当前服务器算薪模型，保留现有核算口径。界面即时公式使用浏览器公式 Worker，最终保存和导出由服务器校验。

API `/api/payroll/workbooks/` 使用现有登录、权限与同源校验，任务结果仅所属账号可读。文件上限 20 MB，展开的压缩包限制 100 MB；任务并发 1、单账号最多 2 个活动任务、总活动任务最多 4 个，超时 120 秒。任务结果短期内存保留，保存的数据和历史版本持久化。

本地运行需 PostgreSQL，迁移 `008_workbooks.sql` 并给原有运行角色新表权限。`npm run build` 自动生成编辑器与公式 Worker。生成文件 `public/salary/editor-assets/` 不提交 Git。

生产发布使用 `运维脚本/deploy-payroll-workbooks.sh <提交SHA> <补丁源码目录>`，需 root、现有 Node 和 PostgreSQL Docker 容器。按清单核验导入/导出控制器，复制当前生产源码进行构建，只加入本功能文件并合并依赖、脚本入口。构建前后核验全部业务源码；发现并行改动则停止。数据库先备份再增量迁移，不替换数据库。程序失败时恢复源码、依赖和构建产物，已新增的数据表保留，避免删除已保存资料。
